01 · La idea principal

¿Qué es un algoritmo?

Un algoritmo es una secuencia ordenada de pasos que permite resolver un problema. En programación, esos pasos deben ser suficientemente claros para que puedan ejecutarse sin ambigüedad.

Preciso

Indica qué debe hacerse y en qué orden. No debe depender de interpretaciones personales.

Definido

Con los mismos datos de entrada debe seguir la misma lógica y producir el resultado previsto.

Finito

Debe terminar después de un número limitado de pasos. Un ciclo que nunca acaba es un error de diseño.

Además, una buena solución debe...

Ser correcta

Resolver realmente el problema planteado y producir resultados válidos.

Ser legible

Usar nombres claros, una estructura sencilla y mensajes comprensibles.

Ser robusta

Prever datos límite o entradas incorrectas cuando el problema lo requiera.

Fases para resolver un problema con el ordenador

Programar no empieza escribiendo código. Un problema se resuelve siguiendo unas fases, y el algoritmo es solo una de ellas:

  1. Análisis.
    Entender qué se pide: qué datos entran, qué resultado debe salir y qué condiciones hay (por ejemplo, «la edad no puede ser negativa»).
  2. Diseño del algoritmo.
    Escribir los pasos en pseudocódigo o dibujarlos en un diagrama de flujo, sin pensar aún en ningún lenguaje.
  3. Codificación.
    Traducir el algoritmo a un lenguaje de programación (en este curso, Java, a partir de la siguiente unidad).
  4. Prueba y depuración.
    Ejecutar con distintos datos, comparar con lo esperado y corregir los fallos que aparezcan.
  5. Documentación y mantenimiento.
    Comentar y explicar el programa para poder entenderlo o modificarlo en el futuro.

Una idea clave: un error detectado en el análisis o el diseño cuesta muy poco de arreglar; el mismo error descubierto al final cuesta mucho más. Por eso en esta unidad pensamos y probamos con papel y lápiz antes de ejecutar.

Ejemplo: un algoritmo de la vida real

«Preparar una tostada»: 1) coger una rebanada; 2) meterla en la tostadora; 3) esperar a que salte; 4) sacarla; 5) untar mantequilla. Es preciso (cada paso es claro), definido (siempre se hace igual) y finito (acaba). «Echar mantequilla hasta que esté bien» no sería un buen paso: es ambiguo.

Objetivo de esta unidadAprender a pensar la solución antes de preocuparnos por la sintaxis de Java. Primero trabajamos la lógica; después la trasladaremos a un lenguaje de programación.

Ejemplo: área de un rectángulo

Entrada: base y altura. Proceso: multiplicarlas. Salida: el área calculada.

03 · Escribir la solución

Pseudocódigo y PSeInt

El pseudocódigo expresa un algoritmo mediante instrucciones fáciles de leer, sin depender todavía de un lenguaje de programación concreto. PSeInt utiliza un pseudolenguaje en castellano y permite ejecutar los algoritmos y visualizar su diagrama de flujo.

Estructura mínima

Algoritmo HolaMundo
    Escribir "Hola mundo";
FinAlgoritmo

Estructura habitual

Algoritmo Nombre
    // Declaraciones
    Definir dato Como Entero;

    // Cuerpo del algoritmo
    Leer dato;
    Escribir dato;
FinAlgoritmo

Cada instrucción termina en ; (PSeInt lo perdona si falta, pero conviene acostumbrarse porque Java sí lo exige). La sangría (los espacios al principio de línea) no es obligatoria, pero hace visible qué instrucciones están dentro de un Si o de un bucle. En PSeInt también puedes encontrar Proceso … FinProceso, que es lo mismo que Algoritmo … FinAlgoritmo.

Comentarios

Un comentario es texto que el programa ignora y que escribimos para las personas. Se usa // para comentar hasta el final de la línea y /* … */ para varias líneas:

// Calcula el área de un rectángulo
/* Autor: Ana
   Fecha: septiembre */
area <- base * altura;   // base por altura

Un buen comentario explica por qué se hace algo, no repite lo que ya dice la instrucción.

En nuestros ejercicios utilizaremos tres ideas básicas: declarar los datos que necesitaremos, leer los valores de entrada y escribir los resultados. Después añadiremos decisiones y bucles.

Forma de trabajarNo intentes memorizar todas las instrucciones. Escribe un ejemplo pequeño, ejecútalo, modifica una línea y observa qué cambia.
04 · Trabajar con información

Variables, tipos de datos y operadores

Una variable es un nombre asociado a un dato cuyo valor puede cambiar durante la ejecución. Es recomendable usar nombres que expliquen qué información contienen.

TipoQué guardaEjemplos
EnteroNúmeros sin decimales0, 18, -3
RealNúmeros con decimales7.5, 21.25
CadenaTexto"Ana", "DAW"
LogicoVerdadero o falsoVerdadero, Falso
 
Definir edad Como Entero;
Definir precio Como Real;
Definir nombre Como Cadena;
Definir encontrado Como Logico;

Se pueden declarar varias variables del mismo tipo en una línea: Definir a, b, c Como Entero;. Los decimales se escriben con punto (7.5), no con coma, y el texto va entre comillas dobles. PSeInt también admite el tipo genérico Numerico (entero o real), pero en esta unidad usaremos Entero y Real porque es lo que luego distinguiremos en Java.

Reglas para los nombres de variable

  • Empiezan por una letra y contienen solo letras, números y guion bajo (nota1, precio_final). No pueden llevar espacios ni acentos.
  • No pueden coincidir con una palabra reservada (Si, Para, Leer…).
  • Por defecto PSeInt no distingue mayúsculas de minúsculas (Edad y edad son la misma variable). Java sí las distingue; es buena idea escribirlas siempre igual.
  • Deben explicar su contenido: precioFinal es mejor que x.

Constantes y literales

Un literal es un valor escrito directamente en el algoritmo (18, 7.5, "Hola", Verdadero). Una constante es un valor que no debe cambiar durante la ejecución, como el IVA. PSeInt no tiene una instrucción especial para declararlas: se usa una variable a la que se asigna el valor una sola vez, y por convención se escribe en MAYÚSCULAS:

IVA <- 0.21;
precioFinal <- precio * (1 + IVA);

Así, si el IVA cambia, se modifica en un único sitio. En Java existirán de verdad (palabra final) y las verás en la UP2.

Precedencia (qué se calcula primero): paréntesis, después ^, luego * / MOD y por último + -. A igual nivel se calcula de izquierda a derecha. Así, 2 + 3 * 4 vale 14, (2 + 3) * 4 vale 20 y 10 - 4 - 3 vale 3.

05 · Primeros programas

Escribir, Leer y asignar

1. Mostrar información con Escribir

Algoritmo Presentacion
    Escribir "Hola";
    Escribir "Estoy aprendiendo programación";
FinAlgoritmo

2. Pedir información con Leer

Algoritmo Saludar
    Definir nombre Como Cadena;

    Escribir "¿Cómo te llamas?";
    Leer nombre;

    Escribir "Hola ", nombre;
FinAlgoritmo

3. Realizar un cálculo

Algoritmo Suma
    Definir a, b, resultado Como Entero;

    Escribir "Introduce el primer número:";
    Leer a;
    Escribir "Introduce el segundo número:";
    Leer b;

    resultado <- a + b;
    Escribir "La suma es ", resultado;
FinAlgoritmo

4. Detalles de Escribir y Leer

  • Escribir admite varios elementos separados por comas y los muestra seguidos, sin añadir espacios: por eso escribimos "Hola " con un espacio dentro de las comillas.
  • Cada Escribir termina en un salto de línea. Para seguir en la misma línea se usa Escribir Sin Saltar.
  • Leer detiene el algoritmo hasta que la persona escribe un valor y pulsa Intro. El valor debe ser del tipo de la variable: si es Entero y escribes 3.5, PSeInt da error.
  • Antes de un Leer conviene un Escribir que explique qué dato se espera; si no, la persona no sabe qué escribir.
Algoritmo Mismalinea
    Escribir Sin Saltar "Hola ";
    Escribir "mundo";
    Escribir "Total: ", 5, " euros";
FinAlgoritmo

Salida:

Hola mundo
Total: 5 euros

5. Ejemplo completo: área de un rectángulo

Algoritmo AreaRectangulo
    Definir base, altura, area Como Real;

    Escribir "Base:";
    Leer base;
    Escribir "Altura:";
    Leer altura;

    area <- base * altura;
    Escribir "El área es ", area;
FinAlgoritmo

Si el usuario escribe 4 y 2.5, la salida es El área es 10 (4 × 2,5 = 10). Fíjate en el orden: primero se leen los datos, luego se calcula y al final se muestra. Si calculases antes de leer, las variables aún no tendrían valor.

Error típicoIntercambiar dos variables con a <- b; b <- a;: tras la primera línea el valor original de a se ha perdido y ambas valen lo mismo. Hace falta una tercera variable: aux <- a; a <- b; b <- aux;. Con a = 1 y b = 2 queda a = 2 y b = 1.

Secuencia recomendada

Escribe → ejecuta → cambia algo → vuelve a ejecutar. Esa comparación permite entender para qué sirve cada instrucción mucho más rápido que memorizar definiciones.

06 · Tomar decisiones

Condicionales: Si y SiNo

Una condición se evalúa como verdadera o falsa. A partir de ese resultado el algoritmo decide qué instrucciones ejecutar.

Condición simple

Si nota >= 5 Entonces
    Escribir "Aprobado";
FinSi

Solo se ejecuta el bloque si la condición es verdadera.

Condición doble

Si edad >= 18 Entonces
    Escribir "Mayor de edad";
SiNo
    Escribir "Menor de edad";
FinSi

Se ejecuta una rama u otra, pero no las dos.

Ejemplo: ¿par o impar?

Algoritmo ParImpar
    Definir n Como Entero;
    Escribir "Número:";
    Leer n;
    Si n MOD 2 = 0 Entonces
        Escribir n, " es par";
    SiNo
        Escribir n, " es impar";
    FinSi
FinAlgoritmo

Un número es par si el resto de dividirlo entre 2 es 0. Con 7 la salida es 7 es impar; con 10, 10 es par; con 0, 0 es par.

Condiciones encadenadas (anidadas)

Cuando hay más de dos casos se coloca un Si dentro del SiNo de otro. Se evalúan en orden y solo se ejecuta la primera rama cuya condición sea verdadera:

Algoritmo Calificacion
    Definir nota Como Real;
    Escribir "Nota:";
    Leer nota;
    Si nota >= 9 Entonces
        Escribir "Sobresaliente";
    SiNo
        Si nota >= 7 Entonces
            Escribir "Notable";
        SiNo
            Si nota >= 5 Entonces
                Escribir "Aprobado";
            SiNo
                Escribir "Suspenso";
            FinSi
        FinSi
    FinSi
FinAlgoritmo
notanota >= 9nota >= 7nota >= 5Salida
9Verdadero(no se evalúa)(no se evalúa)Sobresaliente
6.5FalsoFalsoVerdaderoAprobado
4.99FalsoFalsoFalsoSuspenso

Cada Si necesita su FinSi; cuenta que los cierres coinciden con las aperturas. PSeInt tiene también la estructura Segun para elegir entre muchos valores; no la usaremos en esta unidad.

Error típicoProbar solo con un dato «normal». Los fallos suelen estar en el límite: ¿qué ocurre con nota = 5? ¿Y con 4.99? Elegir >= o > cambia el resultado justo en el valor frontera.
ConsejoAntes de escribir el Si, expresa la condición como una pregunta de respuesta Sí/No. Por ejemplo: «¿la nota es mayor o igual que 5?».
07 · Repetir con control

Mientras, Repetir y Para

Un bucle repite un bloque de instrucciones. La elección depende de cuándo se comprueba la condición y de si conocemos o no el número de repeticiones.

Mientras

Comprueba la condición antes. Puede ejecutarse cero veces.

Mientras n > 0 Hacer
    Escribir n;
    n <- n - 1;
FinMientras

Repetir

Comprueba al final. El bloque se ejecuta al menos una vez.

Repetir
    Leer n;
Hasta Que n > 0

Para

Es apropiado cuando conocemos cuántas repeticiones necesitamos.

Para i <- 1 Hasta 10 Hacer
    Escribir i;
FinPara

Para con otro paso

Por defecto Para avanza de 1 en 1. Con Con Paso se cambia el salto, también hacia atrás:

Para i <- 10 Hasta 0 Con Paso -2 Hacer
    Escribir Sin Saltar i, " ";
FinPara

Muestra 10 8 6 4 2 0. La variable i la modifica el propio Para: no hay que sumar nada dentro.

Ejemplo: suma de los números del 1 al n (acumulador)

Algoritmo SumaHasta
    Definir n, i, suma Como Entero;
    Escribir "Hasta qué número?";
    Leer n;
    suma <- 0;
    Para i <- 1 Hasta n Hacer
        suma <- suma + i;
    FinPara
    Escribir "La suma es ", suma;
FinAlgoritmo

Con n = 5 la variable suma va tomando los valores 0, 1, 3, 6, 10 y 15, y se muestra La suma es 15. Un acumulador es una variable que va guardando un total; debe inicializarse antes del bucle (aquí a 0). Si se olvida, empieza con un valor indefinido y el resultado es erróneo.

Ejemplo: validar un dato con Repetir

Algoritmo ValidarNota
    Definir nota Como Real;
    Repetir
        Escribir "Nota entre 0 y 10:";
        Leer nota;
    Hasta Que nota >= 0 Y nota <= 10
    Escribir "Nota válida: ", nota;
FinAlgoritmo

Si el usuario escribe 15, -2 y 8, la pregunta se hace tres veces y al final se muestra Nota válida: 8. Fíjate: Repetir … Hasta Que se repite mientras la condición sea falsa y termina cuando es verdadera (al revés que Mientras). Por eso aquí la condición describe el dato correcto.

¿Cuál elijo?

  • Sé cuántas veces repetir (10 veces, de 1 a n): Para.
  • No lo sé y puede que no haga falta ni una vez: Mientras (con n = 0, el ejemplo anterior de cuenta atrás no muestra nada).
  • No lo sé y como mínimo debe hacerse una vez (pedir un dato hasta que sea válido): Repetir.
Error clásicoEn un Mientras, alguna instrucción debe modificar los datos que intervienen en la condición. Si nada cambia, podemos crear un bucle infinito.
08 · Ver el algoritmo

Diagramas de flujo u ordinogramas

Un diagrama de flujo representa visualmente la secuencia de un algoritmo. Para el programa utilizaremos un diagrama detallado -también llamado ordinograma- que muestra inicio, operaciones, entradas/salidas, decisiones y final.

Inicio / Fin
Terminal

Marca el comienzo o el final.

Leer / Escribir
Entrada / salida

Datos que entran o información que mostramos.

Proceso
Proceso

Cálculos, asignaciones y acciones.

¿?
Decisión

Condición que abre dos o más caminos.

Ejemplo: determinar si una persona es mayor de edad

Algoritmo MayorEdad
    Definir edad Como Entero;
    Leer edad;

    Si edad >= 18 Entonces
        Escribir "Mayor de edad";
    SiNo
        Escribir "Menor de edad";
    FinSi
FinAlgoritmo

Ejemplo con un bucle: contar de 1 a 3

Un bucle en un diagrama es una decisión de la que sale una flecha que vuelve hacia atrás. Este diagrama representa el algoritmo Contar de la sección de trazas:

Sigue las flechas con el dedo: i vale 1, la condición es Sí, se escribe 1, i pasa a 2 y la flecha vuelve a la decisión. Cuando i vale 4 la respuesta es No y se sale por la derecha hacia el Fin.

Reglas prácticas para dibujarlos

  • Debe existir un inicio claro y un final claro.
  • Todos los símbolos deben estar conectados mediante líneas de flujo.
  • Las flechas indican el orden de ejecución, normalmente de arriba abajo y de izquierda a derecha.
  • En una decisión, identifica las salidas: por ejemplo, Sí y No.
  • Evita cruzar líneas; utiliza un recorrido visual limpio.
  • El diagrama y el pseudocódigo deben representar exactamente la misma lógica.
09 · Comprobar antes de ejecutar

Trazas: seguir un algoritmo paso a paso

Una traza consiste en simular manualmente la ejecución y anotar cómo cambian las variables. Es especialmente útil para encontrar errores en condicionales y bucles.

Ejemplo

Algoritmo Contar
    Definir i Como Entero;
    i <- 1;

    Mientras i <= 3 Hacer
        Escribir i;
        i <- i + 1;
    FinMientras
FinAlgoritmo

Tabla de traza

PasoValor de iSalida
Inicialización1-
Iteración 11 → 21
Iteración 22 → 32
Iteración 33 → 43
Fin4-

La salida completa del algoritmo es 1, 2 y 3, cada número en su línea (cada Escribir salta de línea). Cuando se comprueba i <= 3 con i = 4 la condición es falsa y el bucle termina.

Cómo hacer una traza paso a paso

  1. Prepara una tabla.
    Una columna por variable, una para la condición si hay decisiones o bucles, y una para la salida.
  2. Elige unos datos de entrada concretos.
    Si el algoritmo usa Leer, decide qué valores «escribe» el usuario.
  3. Ejecuta una instrucción por vez, como lo haría el ordenador, y anota el nuevo valor de la variable que cambia.
  4. Compara la salida con lo esperado.
    Si no coincide, has encontrado un error en el algoritmo (o en lo que esperabas).

Ejemplo con dos variables: factorial de 4

Algoritmo Factorial
    Definir i, f Como Entero;
    f <- 1;
    i <- 1;
    Mientras i <= 4 Hacer
        f <- f * i;
        i <- i + 1;
    FinMientras
    Escribir "4! = ", f;
FinAlgoritmo

Prueba de escritorio con casos límite

Una prueba de escritorio es una traza hecha con varios conjuntos de datos elegidos para romper el algoritmo: un caso normal, los valores frontera (el 0, el justo en el límite de una condición, el mínimo y el máximo permitidos) y un caso «raro» (por ejemplo, n = 0 en un bucle). Para Factorial con 4 ya hemos comprobado un caso normal; ¿y si el límite fuera 0? El Mientras no se ejecutaría y f valdría 1 (0! = 1), que es correcto.

Error típicoHacer la traza «de memoria» o suponiendo lo que el algoritmo debería hacer. Hay que ejecutar exactamente lo que está escrito, instrucción por instrucción. Por ejemplo, si se olvida i <- i + 1, la traza muestra que i siempre vale 1, la condición nunca se vuelve falsa y el bucle no acaba: un bucle infinito.
ConsejoSi un bucle no hace lo que esperas, recorre dos o tres iteraciones a mano. Anotar los valores de las variables suele mostrar rápidamente dónde está el error.
10 · Cómo afrontar un problema

Método de trabajo recomendado

  1. Lee el problema y detecta qué te piden.
    No empieces escribiendo instrucciones todavía.
  2. Identifica entrada, proceso y salida.
    Anota los datos necesarios y el resultado que debes obtener.
  3. Describe la solución en lenguaje natural.
    Ej.: leer edad → comprobar si es ≥ 18 → mostrar resultado.
  4. Pásala a pseudocódigo.
    Utiliza únicamente las estructuras que necesitas.
  5. Haz una traza y prueba casos distintos.
    Incluye valores normales, límites y casos problemáticos.
  6. Ejecuta, corrige y simplifica.
    Una solución correcta también debe ser legible.
