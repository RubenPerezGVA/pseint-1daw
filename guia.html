01 · La idea principal

¿Qué es un algoritmo?

Un algoritmo es una secuencia ordenada de pasos que permite resolver un problema. En programación, esos pasos deben ser suficientemente claros para que puedan ejecutarse sin ambigüedad.

Preciso

Indica qué debe hacerse y en qué orden. No debe depender de interpretaciones personales.

Definido

Con los mismos datos de entrada debe seguir la misma lógica y producir el resultado previsto.

Finito

Debe terminar después de un número limitado de pasos. Un ciclo que nunca acaba es un error de diseño.

Además, una buena solución debe...

Ser correcta

Resolver realmente el problema planteado y producir resultados válidos.

Ser legible

Usar nombres claros, una estructura sencilla y mensajes comprensibles.

Ser robusta

Prever datos límite o entradas incorrectas cuando el problema lo requiera.

Objetivo de esta unidadAprender a pensar la solución antes de preocuparnos por la sintaxis de Java. Primero trabajamos la lógica; después la trasladaremos a un lenguaje de programación.

03 · Escribir la solución

Pseudocódigo y PSeInt

El pseudocódigo expresa un algoritmo mediante instrucciones fáciles de leer, sin depender todavía de un lenguaje de programación concreto. PSeInt utiliza un pseudolenguaje en castellano y permite ejecutar los algoritmos y visualizar su diagrama de flujo.

Estructura mínima

Algoritmo HolaMundo
    Escribir "Hola mundo";
FinAlgoritmo

Estructura habitual

Algoritmo Nombre
    // Declaraciones
    Definir dato Como Entero;

    // Cuerpo del algoritmo
    Leer dato;
    Escribir dato;
FinAlgoritmo

En nuestros ejercicios utilizaremos tres ideas básicas: declarar los datos que necesitaremos, leer los valores de entrada y escribir los resultados. Después añadiremos decisiones y bucles.

Forma de trabajarNo intentes memorizar todas las instrucciones. Escribe un ejemplo pequeño, ejecútalo, modifica una línea y observa qué cambia.
04 · Trabajar con información

05 · Primeros programas

Escribir, Leer y asignar

1. Mostrar información con Escribir

Algoritmo Presentacion
    Escribir "Hola";
    Escribir "Estoy aprendiendo programación";
FinAlgoritmo

2. Pedir información con Leer

Algoritmo Saludar
    Definir nombre Como Cadena;

    Escribir "¿Cómo te llamas?";
    Leer nombre;

    Escribir "Hola ", nombre;
FinAlgoritmo

3. Realizar un cálculo

Algoritmo Suma
    Definir a, b, resultado Como Entero;

    Escribir "Introduce el primer número:";
    Leer a;
    Escribir "Introduce el segundo número:";
    Leer b;

    resultado <- a + b;
    Escribir "La suma es ", resultado;
FinAlgoritmo

Secuencia recomendada

Escribe → ejecuta → cambia algo → vuelve a ejecutar. Esa comparación permite entender para qué sirve cada instrucción mucho más rápido que memorizar definiciones.

06 · Tomar decisiones

Condicionales: Si y SiNo

Una condición se evalúa como verdadera o falsa. A partir de ese resultado el algoritmo decide qué instrucciones ejecutar.

Condición simple

Si nota >= 5 Entonces
    Escribir "Aprobado";
FinSi

Solo se ejecuta el bloque si la condición es verdadera.

Condición doble

Si edad >= 18 Entonces
    Escribir "Mayor de edad";
SiNo
    Escribir "Menor de edad";
FinSi

Se ejecuta una rama u otra, pero no las dos.

ConsejoAntes de escribir el Si, expresa la condición como una pregunta de respuesta Sí/No. Por ejemplo: «¿la nota es mayor o igual que 5?».
07 · Repetir con control

Mientras, Repetir y Para

Un bucle repite un bloque de instrucciones. La elección depende de cuándo se comprueba la condición y de si conocemos o no el número de repeticiones.

Mientras

Comprueba la condición antes. Puede ejecutarse cero veces.

Mientras n > 0 Hacer
    Escribir n;
    n <- n - 1;
FinMientras

Repetir

Comprueba al final. El bloque se ejecuta al menos una vez.

Repetir
    Leer n;
Hasta Que n > 0

Para

Es apropiado cuando conocemos cuántas repeticiones necesitamos.

Para i <- 1 Hasta 10 Hacer
    Escribir i;
FinPara
Error clásicoEn un Mientras, alguna instrucción debe modificar los datos que intervienen en la condición. Si nada cambia, podemos crear un bucle infinito.
08 · Ver el algoritmo

Diagramas de flujo u ordinogramas

Un diagrama de flujo representa visualmente la secuencia de un algoritmo. Para el programa utilizaremos un diagrama detallado -también llamado ordinograma- que muestra inicio, operaciones, entradas/salidas, decisiones y final.

Inicio / Fin
Terminal

Marca el comienzo o el final.

Leer / Escribir
Entrada / salida

Datos que entran o información que mostramos.

Proceso
Proceso

Cálculos, asignaciones y acciones.

¿?
Decisión

Condición que abre dos o más caminos.

Ejemplo: determinar si una persona es mayor de edad

Algoritmo MayorEdad
    Definir edad Como Entero;
    Leer edad;

    Si edad >= 18 Entonces
        Escribir "Mayor de edad";
    SiNo
        Escribir "Menor de edad";
    FinSi
FinAlgoritmo

Reglas prácticas para dibujarlos

  • Debe existir un inicio claro y un final claro.
  • Todos los símbolos deben estar conectados mediante líneas de flujo.
  • Las flechas indican el orden de ejecución, normalmente de arriba abajo y de izquierda a derecha.
  • En una decisión, identifica las salidas: por ejemplo, Sí y No.
  • Evita cruzar líneas; utiliza un recorrido visual limpio.
  • El diagrama y el pseudocódigo deben representar exactamente la misma lógica.
09 · Comprobar antes de ejecutar

Trazas: seguir un algoritmo paso a paso

Una traza consiste en simular manualmente la ejecución y anotar cómo cambian las variables. Es especialmente útil para encontrar errores en condicionales y bucles.

Ejemplo

Algoritmo Contar
    Definir i Como Entero;
    i <- 1;

    Mientras i <= 3 Hacer
        Escribir i;
        i <- i + 1;
    FinMientras
FinAlgoritmo

ConsejoSi un bucle no hace lo que esperas, recorre dos o tres iteraciones a mano. Anotar los valores de las variables suele mostrar rápidamente dónde está el error.
10 · Cómo afrontar un problema

Método de trabajo recomendado

  1. Lee el problema y detecta qué te piden.
    No empieces escribiendo instrucciones todavía.
  2. Identifica entrada, proceso y salida.
    Anota los datos necesarios y el resultado que debes obtener.
  3. Describe la solución en lenguaje natural.
    Ej.: leer edad → comprobar si es ≥ 18 → mostrar resultado.
  4. Pásala a pseudocódigo.
    Utiliza únicamente las estructuras que necesitas.
  5. Haz una traza y prueba casos distintos.
    Incluye valores normales, límites y casos problemáticos.
  6. Ejecuta, corrige y simplifica.
    Una solución correcta también debe ser legible.
